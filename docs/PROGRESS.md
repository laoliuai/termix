- [x] Relax `buildinfo.Identity.Matches` to compare `Modified` as an equality field instead of rejecting any dirty side. Surfaced during local smoke as `daemon spawned with mismatched identity (dev@<rev>-dirty vs dev@<rev>-dirty)` — Go's `runtime/debug.ReadBuildInfo` reports `vcs.modified=true` whenever `git status --porcelain` is non-empty (including untracked files like a stray `settings.json` at the repo root), and the previous "dirty → never matches" rule made every `termix start` from a dev workspace fatal: `ensureDaemon` killed the existing daemon, spawned a fresh one from the same dirty tree, then rejected it for the same reason. New rule: both Versions non-empty AND `(Version, Revision, Modified)` all equal. Tradeoff (acknowledged): when both sides are dirty at the same commit, Go's `vcs.revision` is the last commit hash (not a hash of the working tree), so a dev-loop edit that only touches uncommitted code will still reuse the running daemon — callers needing a stronger guarantee must kill the daemon explicitly.
