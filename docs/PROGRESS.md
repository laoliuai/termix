- [x] Watch-with-size protocol slice (pre-v0.4.6). **Bug**: a remote fork (Windows-support port) reproduced a v0.4.4+ regression: every SPA viewer disconnects the moment it connects to the relay and the reconnect supervisor loops for 5 minutes before showing the give-up modal. **Root cause**: v0.4.4's `49a3cad` reversed the SPA's WS-open handshake to `hello.android → client.resize → session.watch` so the daemon would size the tmux pane before `capture-pane` ran. But the relay's `client.resize` handler (introduced in `e43c9fa`) requires `isWatching(peer, sessionID)` to be true and returns `"not watching session"` on miss, which `handleEnvelope`'s caller treats as fatal (`writeError` + `return` + defer-close). So every SPA: relay accepts the WS, ignores `hello.android` (default case `return nil`), rejects `client.resize` with an error, closes the WS — and `session.watch` never reads. The bug shipped in v0.4.4 and survived v0.4.5 + v0.4.6's hotfix slice because release smoke was deferred (per the "ship and iterate" preference) and no v0.4.4/5/6 user re-tested the SPA flow on real prod. The two constraints actually conflict at the protocol layer: SPA needs to resize before snapshot (else capture-pane returns stale-size content), relay needs watch before resize (else unauthenticated peers could drive any pane). Three candidate fixes considered (relay re-auths resize through `AuthorizeWatch`; relay queues pre-watch resize; embed cols/rows on watch) — chose option C: make viewer initialization atomic by moving the grid hint onto `session.watch` itself. **Implementation**: (a) `relayproto` envelopes for `session.watch` and `session.snapshot.request` gain optional `cols`/`rows`; the relay server's `TypeSessionWatch` case calls a new `payloadPositiveUint32` helper (rejects 0/negative/non-integer/overflow) and forwards both fields into the outgoing `snapshot.req` payload (`go/internal/relay/server.go`). (b) `relayclient.SnapshotRequestPayload` gains `Cols/Rows uint32` (`go/internal/relayclient/messages.go`); `Client.handleSnapshotRequest` decodes via the typed struct (no more raw `Payload["session_id"]` cast) and, when cols/rows > 0 and a resize handler is set, calls the resize handler *before* the snapshot handler so tmux is sized correctly when `capture-pane` runs (`go/internal/relayclient/client.go`). (c) SPA `inbound.ts` swaps the WS-open block from `hello → client.resize → session.watch` to `hello → session.watch(cols, rows)`; the runtime ResizeObserver-driven `client.resize` envelope is unchanged (relay's `isWatching` guard still applies, which is correct for that case). `SessionWatchPayload` gains optional `cols?: number; rows?: number` (`web/app/src/protocol/types.ts`).
